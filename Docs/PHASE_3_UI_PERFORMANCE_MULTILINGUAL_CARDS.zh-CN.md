# 第三阶段：训练家终端 UI、顺畅度与中英日卡牌

状态：规划与容量基线已建立（2026-07-30），实施中。

## 一、目标

第三阶段在第二阶段已验收的 229 个按需内容包、完整图鉴与英文卡牌资料之上完成三件事：

1. 将玩家界面统一为原创的“训练家终端 / 图鉴设备”视觉语言，使其具有鲜明的宝可梦冒险氛围，但不复制官方界面、Logo、角色素材或音频。
2. 优化中端 Android 上的列表滚动、页面切换、图片解码、搜索筛选和动画调度；正常操作不能因为全量资料增长而一次加载所有卡图。
3. 卡牌内容扩展为英文 `en`、日文 `ja`、简体中文 `zh-cn`，并把“界面语言”与“卡牌印刷语言”继续保持为两个独立选择。

## 二、已经确认的玩家规则

卡牌语言不是对同一张英文卡做文字翻译，而是独立的实体印刷版本。

- 一个卡牌版本组只有一种已安装语言时，直接显示该卡，不显示无效语言切换器。
- 同组存在两种或三种已安装语言时，详情页显示 `中 / EN / 日` 分段切换。
- 切换后必须一起更换卡图、卡名、所属系列、卡号、稀有度、变体与来源信息。
- 没有对应印刷版的语言不显示空白标签，不机翻、不伪造卡图，也不回退成另一语言后冒充目标语言。
- 全局“卡牌内容语言”决定抽卡、系列列表与默认详情版本；详情页的临时语言切换只影响当前版本组，不偷偷修改全局设置。
- 切换详情语言后仍保持同一逻辑卡组；关闭详情并重新打开时，以全局内容语言优先，否则选择该组实际存在的第一个版本。

## 三、身份与匹配模型

现有 `PrintingDefinition` 继续代表一个确定语言、系列、卡号和变体的实体印刷版。新增独立的跨语言版本组，不破坏收藏数量与抽卡记录：

```text
CrossLanguageCardGroup
  groupId
  members[]
    languageId
    printingId
    sourceCardId
    setId / localId / variantId
  matchMethod
  confidence
  reviewStatus
```

匹配必须保守且可审计：

1. 优先使用来源提供的稳定跨语言身份或经过版本控制的系列映射。
2. 再使用系列、卡号、插画家、宝可梦主体、规则字段和卡图感知特征的组合证据。
3. 自动结果必须记录方法与置信度；有歧义的重印、合辑、不同插画和语言独占卡进入复核清单。
4. 低置信度项目保持为各自独立卡，不为了增加语言按钮而错误合并。
5. 收藏存档继续按 `printingId` 计数；跨语言组只负责浏览和跳转，不合并玩家拥有数量。

## 六、UI 方向

视觉关键词：训练家终端、图鉴设备、探索地图、竞技场记分板。

- 主背景使用深海军蓝；功能面板用暖白/浅灰，避免当前页面全部陷在相近深色中。
- 主要动作使用高辨识红色，信息/选中态使用蓝色，稀有或新获得状态使用电光黄。
- 页头加入原创圆形状态灯与细扫描线；标签和按钮使用胶囊轮廓，不放官方精灵球图标。
- 卡图始终是视觉中心，装饰不得遮挡卡牌文字与编号。
- 页面进入、详情翻面、语言版本切换与下载完成都保留短动画和统一音效；开启“减少动态效果”后用静态颜色/描边替代位移和缩放。
- 动画默认以 30 FPS 低成本调度或一次性过渡完成，不为不可见元素保留每帧任务。

## 七、性能预算

- 首屏不读取不可见卡图；所有大型列表继续使用固定高度虚拟化。
- 同一图片请求去重；离开行、切换语言或关闭详情时取消已经失去消费者的请求。
- 卡图解码与 UI 赋值分离；主线程每帧只提交有限数量结果，避免连续解码造成触控卡顿。
- 收藏/图鉴搜索使用短防抖并复用预计算的规范化搜索键，不在每次按键时遍历和分配全部字符串。
- 语言版本组和物种关联在 Catalog 加载时构建只读索引，详情页不得每次扫描全量 Printings。
- 手机缓存以容量和张数双门槛约束；页面关闭后不能因为事件、调度器或图片视图残留而持续增长。
